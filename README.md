# 手取りシミュレーション（確定申告アンケート）

申告状況を3問で聞き、売上・経費から**手取り額を試算**するアンケート。
白色申告の方には「2027年に青色申告へ切り替えると手取りがこれだけ増える」を
グラフで提示する。`taxnap-survey-loan` を土台にした単一HTML完結の構成。

- 公開URL: GitHub Pages（Settings > Pages > Branch: `main` / `/root`）
- 回答先: Google スプレッドシート（Google Apps Script 経由）

## ファイル

| ファイル | 用途 |
|---|---|
| `index.html` | 本体（単一HTML完結）。設問は `QUESTIONS`、税額計算は `tedori()`、控除推定は `estimate()` |
| `gas/Code.gs` | 回答受け口。スプレッドシートに1行追記する |
| `happy.riv` / `snappy.png` / `taxnap_logo.png` | ブランド素材 |

## 選択肢の表示（label / sub）

選択肢は `text`（**集計キー。変更しない**）と、表示用の `label` / `sub` を分けて持つ。
長い選択肢は `sub` に小さい2行目として出し、括弧内やソフト名が中途半端な位置で
折り返さないようにしている。`estimate()` は `text` で判定するため、表示だけ変えても
推定ロジックとスプレッドシートの値は変わらない。

```js
{emoji:'💻', text:'会計ソフトで自分でした（freee・マネフォ・弥生など）',
             label:'会計ソフトで自分でした', sub:'freee・マネーフォワード・弥生 など'},
```

設問文・ヒントにも `word-break:auto-phrase` を当て、長文は `<br>` で明示的に改行位置を
指定している（375px 幅で検証済み）。

## 配布のしかた（URLパラメータ）

**HTMLは1つ。会社・対象者はURLで渡す。** リポを複製したり会社名を回答者に入力させたりしない。

```
https://txto-inc.github.io/taxnap-survey-tedori/?c=eclart&r=mgr     ← マネージャー向け（説明会当日）
https://txto-inc.github.io/taxnap-survey-tedori/?c=eclart&r=staff   ← 美容師向け（後日）
```

| パラメータ | 値 | 効果 |
|---|---|---|
| `c` | 会社コード（`eclart` / `gotoday` / `lispo` …） | シートの「会社名」「会社コード」列に記録 |
| `r` | `mgr` / `staff`（既定） | `mgr` のとき結果画面の下に**感想セクション**が出る |

パラメータなしでも動く（`直接配布` / `スタッフ` として記録）。QRコードにして
スライドや配布物に載せられる。

### 新しい提携先を増やすとき

`index.html` の `COMPANIES` に1行足すだけ。**HTMLの複製はしない**（複製すると
税制改正のたびに全ファイルを直すことになり、必ず片方が古くなる）。

```js
const COMPANIES = {
  eclart:  '株式会社ECLART',
  gotoday: 'GO TODAY',
  // ここに追加
};
```

未登録のコードを渡してもコードがそのまま記録されるので、急ぎなら追記なしでも配れる。

## 回答データ（2シート構成）

| シート | 中身 | いつ入るか |
|---|---|---|
| `回答` | 試算アンケート本編（会社名・対象者・申告状況・売上・経費・手取り・差額） | 結果表示時（全員） |
| `MGR感想` | マネージャーの感想（案内できそうか・分かりにくかった点・満足度） | 感想の送信時（`r=mgr` のみ） |

`_kind`（`survey` / `feedback`）で GAS 側が振り分ける。同じスプレッドシート内の別シートなので
デプロイは1つで済む。会社別の集計は「会社コード」列でフィルタする。

### MGR感想の設問（3問・すべて選択式）

| # | 設問 | 形式 | 必須 | 何を判断するか |
|---|---|---|---|---|
| Q1 | この内容を、美容師の皆さまにご案内いただけそうですか | 単一選択4択 | 必須 | **STEP 2 に進んでよいか** |
| Q2 | 分かりにくかった点があれば | 複数選択＋その他 | 任意 | どこを直すか |
| Q3 | 本日の説明会の満足度 | 5段階 | 必須 | 説明会の評価 |

**Q1 は「理解できたか × 案内したいか」の2軸を1問に畳んでいる。** どちらに問題があるかで
打ち手が変わるため、選択肢側で軸を切り分けてある。

| 回答 | 意味 | 打ち手 |
|---|---|---|
| ① 理解できた・積極的に案内したい | 問題なし | STEP 2 へ進む |
| ② 理解できたが案内は難しそう | **提案内容**が刺さっていない | 訴求の見直し |
| ③ 案内したいが理解できなかった | **説明**が届いていない（意欲はある） | 資料・説明の見直し |
| ④ あまり理解できなかった | 説明が届いていない | 同上 |

Q2 の「特になし」は排他選択（他項目と同時に選べない）。「その他」を選んだときだけ
自由記述が開き、外すと入力内容もクリアされる（選択と記述の食い違いを防ぐため）。

## 設問構成（全8問・約2分）

| # | 設問 | 何のために聞くか |
|---|---|---|
| Q1 | 確定申告のしかた | 記帳方法（複式／簡易）の推定 |
| Q2 | 申告書の提出方法 | e-Tax か書面か → 控除額が55万/65万で分かれる |
| Q3 | 青色申告承認申請書を出したか | 青色/白色の判定（**これが無いと青色にできない**） |
| Q4 | 1年間の売上 | 計算の入力（200/300/400/500/700/1000万のチップ＋直接入力） |
| Q5 | 1年間の経費 | 計算の入力（「売上の◯%」チップ＋直接入力） |
| Q6 | 年齢（39歳以下 / 40歳以上） | 40歳以上は介護保険料が加算される |
| Q7 | 健康保険（国保 / 家族の扶養） | 国保計算か概算かの分岐 |
| — | メールアドレス | 結果表示の前に取得（リード獲得） |

Q6・Q7 は手取り額が数万円変わるため入れている。これ以上の精度（居住自治体・
生命保険料控除・扶養家族数など）は離脱とのトレードオフで**あえて聞いていない**。

## 控除額の推定ロジック

Q1〜Q3 から記帳方法を推定し、下表の控除額を当てる。**推定結果は結果画面に
「こう推定しました」と明示**し、違う場合は選び直せるリンクを置いている。

| 記帳方法 | 2026年分 | 2027年分以降 | 増減 |
|---|---|---|---|
| 白色申告 | 0円 | 0円 | ±0 |
| 青色・簡易簿記 | 10万円 | 10万円 | ±0 |
| 青色・複式簿記＋書面申告 | 55万円 | **10万円** | **▲45万円** |
| 青色・複式簿記＋e-Tax | 65万円 | 65万円 | ±0 |
| 上記＋優良な電子帳簿／デジタルシームレス保存 | 65万円 | **75万円** | **+10万円** |

推定の分岐:

- Q3「出していない」「覚えていない」→ **白色**として試算（青色の要件を満たせないため）
- Q3「出した」＋ Q1 が税理士 or 会計ソフト → **複式簿記**
  - Q2 が e-Tax → 65万円 / 書面 → 55万円
- Q3「出した」＋ Q1 が手書き・税務署・未申告 → **簡易簿記（10万円）**

## 結果画面の出し分け

| 推定 | 出るもの |
|---|---|
| 白色・簡易簿記 | **差額ヒーロー**（最上部）＋ **軸つき2本棒グラフ**（そのまま vs 2027年青色75万） |
| 青色・複式＋書面 | ⚠️ **警告**（2027年に55万→10万へ下がる）＋ e-Tax化で取り戻せる額 |
| 青色・複式＋e-Tax | 優良な電子帳簿で +10万円控除 → 手取り増分 |
| 事業所得が低く差が出ない | グラフを出さず「いまの所得では差が出ません」の案内に切替 |

### 結果画面の並び順

差額（＋◯◯円/年）を**最上部**に置いている。手取り額より「増える額」が訴求の核で、
1画面目に入らないとスクロールされないため。順序は 差額 → グラフ → いまの手取り → 推定 → 内訳。

### 内訳（お金の流れ）の構成

**① 事業のもうけ（売上−経費=事業所得）→ ② 差し引かれるもの（税金・保険料）→ ③ 手取り**
の3ブロックに分け、縦に読むと引き算が必ず成立するようにしている（② の合計を ① から引くと ③）。

**青色申告特別控除は金額の引き算列に入れない。** 出ていくお金ではなく課税所得を減らすだけで、
同じ「−」列に並べると縦計が合わず誤解を招くため、①の下に参考値（緑の注記）として置く。

税金の明細（所得税・住民税・個人事業税・国保＋年金）は既定で畳み、
「▸ 税金・保険料の内訳を見る」で展開する。畳んだ状態の情報量を優先した。

### グラフの縦軸

**縦軸は0円からではなく、2本の値をはさむ範囲に拡大している**（10万円刻み）。0基準だと
差が全体の1〜2%にしか見えず増加が伝わらないため。誇張表現になるので、軸の目盛りと
「拡大して表示しています」の注記を必ず併記する（外さないこと）。

**グラフは必ず 2027年分どうしで比較する。** 2026年分（令和8年分）は基礎控除の
上乗せがあるため、2026年の白色と2027年の青色を並べると税制改正の影響が混ざり、
申告方法の差が正しく出ない（売上500万・経費200万で +165,925円 と過小に出てしまう）。
ヒーローの手取り額だけは「今年実際に払う額」なので 2026年分で表示している。

## 税理士法との関係（配布前に必読）

**本ツールは税理士法上の「税務相談」に該当しない設計。** 根拠は次の3点。

1. **人が相談に応じていない** — 入力値に固定の計算式が適用されるだけで、回答・指示・意見表明をする主体がいない
2. **仮定計算である** — 実際の帳簿ではなく、本人が入力した概算の売上・経費に基づく試算
3. **申告書の作成・提出に関与しない** — 税理士法2条1項3号が要求する「申告等に関し」の関与がない

同法2条1項3号の「税務相談」は「租税の課税標準等の計算に関する事項について**相談に応ずること**」であり、
判例・実務解釈上、**一般的な税法の解説**や**仮設例に基づく税額の計算**は該当しないと整理されている
（該当するのは「納税義務者の具体的事実」を対象とする回答）。freee にも同種の税額シミュレーション
（青色/白色の控除差の確認を含む）が搭載されており、業界の前例がある。

### ⚠️ 運用上の注意（ツールではなく人の対応が論点）

**説明会・対面で「私の場合はどうですか」に個別に答えると、そこは税務相談に該当し得る。**
税理士法52条は無償でも適用される（無償独占、2年以下の拘禁刑または100万円以下の罰金）。

- ✅ できる: 制度の一般的な説明、本ツールでの試算、「青色申告とは何か」の解説
- ❌ 避ける: 特定の個人の売上・経費・家族構成を前提にした個別回答、「この経費は入れて大丈夫」等の判断
- 返し方: 「個別のご質問は税理士におつなぎします」

社内の既存整理（`03_PRODUCT/analysis/20260731_税理士法人連携_数値シミュレーションと法的検討.md`）の
結論「アプリ・社員が個別の税務相談に踏み込まない線引き徹底」と同じ原則。

### 免責表示（外さないこと）

結果画面の**金額の直下**に「モデル前提による概算です」を常設している（末尾の詳細な前提リストとは別）。
金額だけが独り歩きしないための措置なので、レイアウト変更時も金額と同じ視野に残す。

## 税額計算の正本と検証

計算ロジックの参照実装は
`taxnap-cowork/03_PRODUCT/alliance/eclart/20260825_ECLART_手取り試算.py`。
`index.html` の `tedori()` はこれと同一ロジックで、次の値が一致することを検証済み。

| 条件 | 白色 | 青色75万 | 差額 |
|---|---|---|---|
| 売上500万・経費200万・2027年分 | 2,140,441円 | 2,321,666円 | **+181,225円** |

**ロジックを変更したときは必ず上記3値を再確認する。**

### 計算の前提

- 東京23区・単身・インボイス未登録
- 国民健康保険: 所得割 10.67%（40歳以上は+2.29%）／均等割 66,300円（同+16,200円）・賦課限度額 109万円
- 国民年金: 年額 215,040円
- 個人事業税: 第3種5%・事業主控除290万円（**青色申告特別控除は事業税に適用されない**）
- 基礎控除: 2026年分は令和8年分の上乗せあり、2027年分以降は恒久措置58万円
- 住民税: 所得割10%＋均等割5,000円、合計所得45万円以下は非課税
- 各種控除（生命保険料・小規模企業共済・扶養）は含まない

## GASデプロイ手順

`taxnap-survey-loan/README.md` の手順と同一。要点:

1. https://sheets.new でスプレッドシートを作る
2. 拡張機能 > Apps Script に `gas/Code.gs` を貼る
3. プロジェクトの設定 > スクリプトプロパティに `POST_TOKEN` を登録（`openssl rand -hex 12`）
4. デプロイ > 新しいデプロイ > ウェブアプリ / 実行=自分 / **アクセス=全員**
5. 発行された `/exec` URL を `index.html` の「【変更箇所①】」に貼る

```js
const GAS_URL = 'https://script.google.com/macros/s/AKfycb.../exec';
const POST_TOKEN = 'taxnap_tedori_2026_xxxxxx';
```

> 修正時は「デプロイを管理 > ✏️編集 > 新バージョン」。「新しいデプロイ」は別URLになる。

## つまずきやすい点

| 症状 | 原因と対処 |
|---|---|
| 回答してもシートに行が増えない | ①アクセス権が「全員」でない ②`POST_TOKEN` 不一致 ③URLが `/dev`（`/exec` が正） |
| CORS エラーがコンソールに出る | 正常。`mode:'no-cors'` のためレスポンスは読めない |
| 手取りがマイナスになる | 売上が国民年金＋均等割を下回る場合は算術上正しい。結果画面に免除制度の注記を出している |
| Rive のキャラが出ない | `happy.riv` が同階層にあるか、CDN がブロックされていないか |

## 分析するとき

`推定した記帳方法・控除` 列で白色/青色の分布が取れる。`差額(2027年どうし)` は
そのまま「切り替えで増える手取り」の分布になるため、訴求額の根拠に使える。
